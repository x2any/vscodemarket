# ADR-0008: 不设独立文档站,文档以 Tooltip + 内嵌文档区承载,中英双语

**状态**: Accepted
**日期**: 2026-08-28
**决策者**: 产品负责人 + 前端

## 背景

需求提到"在合适的页面上提供必要的说明文档"。

候选形态:

- (a) 静态 Markdown + 版本号插值
- (b) 纯静态 Markdown
- (c) Tooltip + 内嵌文档区(主站内)
- (d) 后台可编辑 Wiki

## 决策

**采用 (c):Tooltip + 内嵌文档区。不设独立文档站。提供中英双语切换。**

文档主题(与 5 类功能场景一一对应):

1. **客户端安装**:Windows / macOS / Linux 三平台安装步骤与验证
2. **服务端安装**:在内网机器上获取并运行 vscode-server
3. **服务端启动与连接**:启动 vscode-server、客户端 Remote-SSH 连接流程
4. **离线导入扩展**:在内网机器上从 .vsix 文件手动安装扩展
5. **排错 FAQ**:连接失败、commit hash 不匹配、端口冲突

## 理由

- **与功能就近**:用户每一步操作旁就有提示,无须切换页面。
- **零独立运维**:无路由、无版本号管理、无独立部署。
- **双语就够国际化**:海外内网用户(罕见但存在)也能用。

## 后果

- 不存在 `/docs`、`/docs/:slug` 等独立路由。
- 文档内容作为前端资源,与 UI 组件共置;在 i18n bundle 里以 JSON/Markdown 形式存在。
- 双语切换走前端 i18n 方案(Element Plus 自带 vue-i18n 集成良好)。
- 无版本号插值(配合 ADR-0002 完全实时数据源,任何时刻版本都是最新)。

## 替代方案

- **(a) 版本号插值**:否决。完全实时模式下,版本号每请求都新鲜,无须插值。
- **(b) 纯静态 Markdown**:否决。分散在多个页面不易维护,不如 Tooltip + 内嵌区聚合。
- **(d) Wiki**:否决。后台编辑器会引入用户系统、版本控制,违背 ADR-0003。
