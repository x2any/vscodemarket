# ADR-0004: 不做下载/打包脚本,仅提供内网部署辅助脚本

**状态**: Accepted
**日期**: 2026-08-28
**决策者**: 产品负责人

## 背景

最初设想:"脚本下载"功能可能含三种形态:

1. 一键 wget/curl 脚本(在公网下载所有依赖)
2. 打包 tar.gz 脚本(完全断网场景下,公网下载后打包)
3. 内网部署辅助脚本(用户下载后在内网机器上启动 vscode-server、加载扩展)

业务需求明确后,前两种已不存在(用户自己用浏览器/U 盘拷贝)。**只有第三种真正需要**。

## 决策

**VSCodeMarket 提供"内网部署辅助脚本"。明确不含任何下载、打包、批量下载功能。**

辅助脚本形态:

- 嵌入页面(Tooltip 内或"复制脚本"按钮旁)
- 典型内容:在 Linux 上启动 `vscode-server` 的命令、把 `.vsix` 文件用 `code --install-extension` 装入客户端、解压 tarball 的命令
- 静态 Markdown 片段,后端无动态生成逻辑

## 理由

- **真实痛点**:用户拷到内网后,下一步是"怎么用",脚本片段能省下翻 README 的时间。
- **不增加后端复杂度**:脚本片段就是字符串常量,无须 API、无须下载、无须会话。
- **风险面最小**:脚本不下载任何东西,不接触用户主机,不涉及凭据。

## 后果

- 不存在 `/api/script`、不存在打包下载、不存在 docker 镜像导出。
- 后端无须任何脚本生成器。
- 脚本片段作为前端静态资源,与文档区共置。

## 替代方案

- **动态生成 .sh 文件**:否决。无收益,徒增后端表面积。
