# ADR-0010: 引入事件日志(完整日志 + IP)与多维热门榜单

**状态**: Accepted
**日期**: 2026-08-28
**决策者**: 产品负责人
**取代**: ADR-0002、ADR-0003(均标 Superseded)

## 背景

产品新增需求:
- 记录用户搜索与下载行为
- 在页面上展示热门下载 / 热门搜索
- 按客户端 / 服务端 / 插件维度
- 按时间周期维度(24h/7d/30d)
- 未来以地区维度做网站统计

此需求与 ADR-0002("无 DB")、ADR-0003("不写访问日志")正面冲突。

## 决策

**推翻 ADR-0002 与 ADR-0003,采纳新规则:**

1. **后端持久化用户行为日志**,每条事件包含:
   - 事件类型(`search` / `download`)
   - 目标对象(扩展 ID 或客户端/服务端版本号)
   - 原始搜索关键词(若是 search)
   - 请求者 IP
   - 请求时间(UTC)
   - 由 IP 解析的国家/地区码(用于地区维度统计)
2. **不引入用户系统**:仍无登录、无 Cookie 持久身份;以 IP 作为匿名化的最小单元。
3. **存储**:SQLite 文件(详见 ADR-0011)。
4. **不做反作弊/限频**(详见 ADR-0012)。
5. **热门榜单三维度**:
   - 物维度:客户端 / 服务端 / 扩展
   - 时间维度:24h / 7d / 30d
   - 地理维度(预留):同一榜单可按地区过滤(后期启用,本期 UI 不暴露)

## 理由

- **业务刚需**:热门榜单是发现效应核心,没有它大量长尾扩展没人用。
- **公网应用、隐私已外部化**:"完整日志 + IP"是公网通用做法(等同 Google Analytics / Umami),不存在"内网隐私边界"。
- **地区统计为产品差异化**:产品方明确要走地区维度,需要 IP→Geo 映射。
- **匿名化足够**:有 IP 无 UA/无指纹,符合"最小化原则"。

## 后果

- 引入 SQLite + GORM(ADR-0011)
- 引入 IP→Geo 映射(ADR-0013)
- 所有前端"下载按钮"和"搜索框提交"都触发后端埋点
- 排行榜 UI 是新页面/区块
- ADR-0002 与 ADR-0003 标记 Superseded,引用本 ADR

## 替代方案

- **(a) 只聚合,不计日志**:产品方明确要"完整日志",否决。
- **(b) 用户系统 + UID**:与"公网零摩擦"定位冲突,否决。
- **(c) 接 Plausible / Umami**:本项目自带数据更可控,且榜单需要与自家业务(扩展 ID)关联,第三方分析做不到。
